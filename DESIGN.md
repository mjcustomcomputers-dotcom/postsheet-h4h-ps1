# Post Sheet: Ability and Purpose Crew Network - One-Page Engineering Design

## 1. Problem Inversion: Why Full Rosters Still Fail
Conventional hackathon team boards filter people by static profile badges, cities, or colleges and stop once seats fill. Yet a nominally "full" four-person roster still fails to ship if one versatile builder is double-booked across two simultaneous critical-path tasks (a Hall capacity deficit; Hall, 1935) or if a backend handoff finishes after a teammate's available UTC window. Conversely, two builders 11.5 hours apart with zero simultaneous overlap can ship ahead of schedule when their directed asynchronous handoff windows align.

## 2. Architecture: Two Concurrent Network Layers, Three Separated Execution Paths
- **Layer A: Serialized Membership Authority (`src/authority.mjs`):** Owns bounded team capacity, event-wide one-team-per-person uniqueness, hashed single-use invitations, deterministic leader succession, explicit leadership transfer, last-member team auto-deletion, and attributable audit logging inside a single SQLite `BEGIN IMMEDIATE` WAL transaction. Server-side clocks and bearer subjects govern all commits; client-forged `actorId` or `now` fields are ignored.
- **Layer B: Local-First Peer Collaboration and Relayed Authority (`src/peer-envelope.mjs`, `src/peer-receipts.mjs`, `src/synchronicity-ext.mjs`):** Exchanges per-event `HKDF-SHA256` derived `AES-256-GCM` encrypted, `P-256` ECDSA author-signed collaboration notes (`PEER_ARTIFACT_ONLY`) deduplicated via a `WITHOUT ROWID` SQLite receipt ledger and checked for schedule collisions via `contextGlueOrExplain`. When a participant loses direct WAN connectivity, their browser retains a SHA-256 invite-scoped `opId` (`web/src/claim-operation.js`), mints a narrow 10-minute relay warrant (`aud: h4h-ps1-relay-warrant`), and forwards the claim through an uplinked peer (`/api/peer/relay-claim`) to Layer A. Reconnecting and retrying directly returns `replayed: true` with zero duplicate admissions (Bailis et al., 2014).
- **Three Decoupled Runtime Paths:** (1) `GET /board` uses an indexed paginated SQLite projection (`O(page)`) paired with SSE revision notifications, never blocking on solver search; (2) `POST /api/plan` and `/api/recommendations` execute bounded deterministic planning; (3) membership mutations execute short `BEGIN IMMEDIATE` transactions.

## 3. Goal-Conditioned Synchronicity R5 Formulation
For objective $g$ with task DAG $(V, E)$, durations $d_j$, handoff lags $\ell_{i,j}$, and contributor windows $W_u$:
1. **Backward Critical-Path Slack (Lawler/Jackson EDD):** Computes $LS_j = LF_j - d_j$ backward from $T_{\text{deadline}}$ (Jackson, 1955; Lawler, 1973) so urgent tasks schedule ahead of flexible tasks, specialists leave multi-skilled teammates free for bottleneck roles, and parallel branches evaluate via $\max_{(i,j)\in E}(EF_i + \ell_{i,j})$ across exact event-point starts rather than naive serial sums.
2. **Four-Valued Evidence and Wildcard Omega (`src/synchronicity-solvers.mjs`):** Represents task evidence in $\{0,1\}^2$ (`supported`, `refuted`, `conflicting`, `unknown`; Belnap, 1977) and partitions unresolved skill wildcards $\Omega_\sigma$ ($|\Omega_\sigma| \le 4096$). When $\exists a\,\forall \omega \in \Omega_\sigma: F_g(a,\omega)$, the minimum-sufficient policy emits `ALREADY_SUFFICIENT` and asks zero questions; when contingent, Shannon mutual information $I(\text{Feasible}; X_k)$ selects the single highest-gain verification prompt (Shannon, 1948).
3. **Parallel Hall Witness and Zero-Displacement Repair:** Separates sequential window misses from genuine simultaneous role contention ($|N(K)| < |K|$), proposing repairs that preserve existing committed teammates (Demirovic et al., 2018) and ranking candidates across merged interval-union overlap and directed asynchronous UTC baton passes.

## 4. Key Trade-Off and Verification Summary
Single-node SQLite WAL with `BEGIN IMMEDIATE` guarantees strict serializability, zero split-brain overfills across 50 concurrent claimants, and `36.68 ms` `p95` board latency at 100 concurrent clients on a single free-tier container, trading multi-region write sharding for provable single-event invariant safety (directly portable to per-event Cloudflare Durable Objects). Verified by 176 automated suite assertions (`59` HTTP/race/Python-SQLite gate checks and `117` Node cryptographic, relay, solver, matcher-labs, and security subtests) alongside `5` 10,000-user / 2,000-team load-gate checks.
