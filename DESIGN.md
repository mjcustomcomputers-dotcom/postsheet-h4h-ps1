# Post Sheet: Ability and Purpose Crew Network - One-Page Engineering Design

## 1. Problem Inversion: Why Full Rosters Still Fail
Conventional hackathon team boards filter people by static profile badges, cities, or colleges and stop once seats fill. Yet a nominally "full" four-person roster still fails to ship if one versatile builder is double-booked across two simultaneous critical-path tasks (a Hall capacity deficit; Hall, 1935) or if a backend handoff finishes after a teammate's available UTC window. Conversely, two builders 11.5 hours apart with zero simultaneous overlap can ship ahead of schedule when their directed asynchronous handoff windows align.

## 2. Data Model, Two-Layer Architecture, and Race Prevention
- **Relational Data Model (SQLite WAL):** Six normalized Layer-A tables enforce storage-level invariants: `events` (`id, min_size, max_size`), `teams` (`id, event_id, name, leader_id, max_size, version`), `membership` (`PRIMARY KEY (team_id, user_id)` plus `UNIQUE (event_id, user_id)` for event-wide one-team-per-person exclusivity), `invites` (`code_hash` storing `SHA-256(code)` with `0` plaintext codes, `expires_at`, `used_by`, `used_at`), `operations` (`PRIMARY KEY (event_id, actor_id, op_id)` storing `request_hash` and serialized JSON response for idempotent retries), and append-only `audit` (`seq, event_id, team_id, actor_id, action, detail_json, at`). Layer B stores encrypted collaboration notes in a `WITHOUT ROWID` `peer_receipts` replay ledger.
- **How Races Are Prevented (`src/authority.mjs`):** Every seat mutation (`create`, `invite`, `claim`, `leave`, `transferLeader`) runs inside a single synchronous SQLite `BEGIN IMMEDIATE` WAL transaction. Acquiring the reserved write lock upfront eliminates the async read-then-write race window: when 50 parallel HTTP claimants target one remaining seat, claimant 1 commits `size = max_size` and claimants 2..50 deterministically observe the updated count or `UNIQUE (event_id, user_id)` constraint, returning `1` HTTP `200` winner and `49` structured HTTP `409` rejections with zero overfills. Server-monotonic clocks enforce invite expiry (`410 INVITE_EXPIRED`), departure promotes the earliest `joined_at` member, and the final departure deletes the empty team row atomically.
- **Layer B Offline Peer Relay and Three Runtime Paths:** Collaboration notes use per-event `HKDF-SHA256` derived `AES-256-GCM` encryption and `P-256` ECDSA signatures (`PEER_ARTIFACT_ONLY`). Under WAN loss, the browser persists an invite-scoped SHA-256 `opId` (`web/src/claim-operation.js`), mints a 10-minute scoped warrant (`aud: h4h-ps1-relay-warrant`), and relays the claim through an uplinked teammate (`/api/peer/relay-claim`); direct reconnect replays the original receipt (`replayed: true`). Runtime traffic splits cleanly across (1) indexed `O(page)` `GET /board` reads + SSE revision push, (2) bounded R5 solver evaluation, and (3) microsecond `BEGIN IMMEDIATE` seat commits.

## 3. Goal-Conditioned Synchronicity R5 Formulation
For objective $g$ with task DAG $(V, E)$, durations $d_j$, handoff lags $\ell_{i,j}$, and contributor windows $W_u$:
1. **Backward Critical-Path Slack (Lawler/Jackson EDD):** Computes $LS_j = LF_j - d_j$ backward from $T_{\text{deadline}}$ (Jackson, 1955; Lawler, 1973) so urgent tasks schedule ahead of flexible tasks, specialists leave multi-skilled teammates free for bottleneck roles, and parallel branches evaluate via $\max_{(i,j)\in E}(EF_i + \ell_{i,j})$ across exact event-point starts.
2. **Four-Valued Evidence and Wildcard Omega (`src/synchronicity-solvers.mjs`):** Represents task evidence in $\{0,1\}^2$ (`supported`, `refuted`, `conflicting`, `unknown`; Belnap, 1977) and partitions unresolved skill wildcards $\Omega_\sigma$ ($|\Omega_\sigma| \le 4096$). When $\exists a\,\forall \omega \in \Omega_\sigma: F_g(a,\omega)$, the minimum-sufficient policy emits `ALREADY_SUFFICIENT` and asks zero questions; when contingent, Shannon mutual information $I(\text{Feasible}; X_k)$ selects the single highest-gain verification prompt (Shannon, 1948).
3. **Parallel Hall Witness and Zero-Displacement Repair:** Separates sequential window misses from simultaneous role contention ($|N(K)| < |K|$), proposing repairs that preserve committed teammates (Demirovic et al., 2018) and ranking candidates across merged interval-union overlap and directed asynchronous UTC baton passes.

## 4. Trade-Offs Made
- **Single-Writer SQLite WAL vs. Distributed Locks/ORMs:** Trades multi-node write sharding inside a single event for strict serializability, zero network lock hops, and `36.68 ms` `p95` `/board` latency at 100 concurrent clients on a single container.
- **SSE + Demand-Driven Cognitive Relief UI vs. WebSockets/Heavy Animation:** Uses lightweight one-way SSE invalidation instead of stateful WebSocket rooms, and renders matte Affordalume task shading at `0` idle GPU frames per second (`AffordalumeCgiStage.jsx`) to preserve WCAG 2.2 AA / Section 508 low-glare readability.

## 5. What I Would Do With One More Week
1. **Per-Event Horizontal Sharding:** Route each `event_id` to an isolated SQLite WAL shard (or Cloudflare Durable Object) so thousands of concurrent hackathons scale horizontally while keeping strict `BEGIN IMMEDIATE` serializability inside each event.
2. **Continuous Litestream WAL Replication & Hash-Chained Audit Proofs:** Stream WAL frames to S3/R2 object storage for sub-second point-in-time recovery and link `audit` rows with rolling `SHA-256` Merkle digests for tamper-evident organizer exports.
3. **Calendar ICS Sync & WebAuthn Relay Warrants:** Import live multi-day contributor busy blocks (`iCal`) directly into $W_u$ windows and bind offline peer-relay warrants to hardware-backed WebAuthn passkeys.
